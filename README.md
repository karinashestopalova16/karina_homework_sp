# Виджет банковских операций клиента

## Описание
Виджет банковских операций клиента - приложение для работы с данными банковских операций клиента. Позволяет маскировать данные счета или карты, фильтровать операции по статусу или дате свершения.

## Структура

- **data/operations.json** — файл с данными банковских операций в формате JSON.

- **src/masks.py** — функции для маскировки номеров банковских карт и счетов.

- **src/processing.py** — функции для фильтрации операций по статусу и сортировки по дате.

- **src/widget.py** — функции для обработки и форматирования данных банковских операций.

- **src/generators.py** — функции-генераторы для фильтрации операций по валюте, получения описаний транзакций и генерации номеров карт.

- **src/decorators.py** — декоратор log для записи информации о вызовах функций, результатах выполнения и возникающих исключениях.

- **src/utils.py** — функция для чтения данных банковских операций из JSON-файла.

- **src/external_api.py** — функция для конвертации сумм транзакций в рубли с использованием внешнего API.

- **logs/** — папка для хранения журналов работы приложения.

- **logs/masks.log** — журнал работы функций маскировки номеров карт и счетов.

- **logs/utils.log** — журнал чтения и проверки данных банковских операций из JSON-файлов.

## Установка

1. Клонируйте репозиторий
```
git clone git@github.com:karinashestopalova16/karina_homework_sp.git
```

2. Установите зависимости
```
poetry install
```

3. Настройте переменные окружения для работы с API

Создайте файл `.env` на основе шаблона `.env.example` и укажите свой API-ключ:
```
EXCHANGE_RATES_API_KEY=ваш_api_ключ
```
_Обратите внимание, что файл .env должен быть в .gitignore_

## Использование
Модуль `masks`

Функции модуля masks используются для маскировки номеров карт и счетов.

Пример:
```
get_mask_card_number("1234567812345678")
>>> 1234 56** **** 5678
get_mask_account("12345678901234567890")
>>> **7890
```

Модуль `processing`

Функция `filter_by_state` используется для фильтрации банковских операций по статусу.

Пример:
```
filter_by_state(
    [
        {"id": 41428829, "state": "EXECUTED", "date": "2019-07-03T18:35:29.512364"},
        {"id": 939719570, "state": "EXECUTED", "date": "2018-06-30T02:08:58.425572"},
        {"id": 594226727, "state": "CANCELED", "date": "2018-09-12T21:27:25.241689"},
    ]
)
```

Функция `sort_by_date` используется для сортировки списка операций по дате.

Пример:
```
sort_by_date(
    [
        {"id": 41428829, "state": "EXECUTED", "date": "2019-07-03T18:35:29.512364"},
        {"id": 939719570, "state": "EXECUTED", "date": "2018-06-30T02:08:58.425572"},
        {"id": 594226727, "state": "CANCELED", "date": "2018-09-12T21:27:25.241689"},
    ]
)
```

Модуль `widget`

Модуль `widget` используется для обработки данных банковской операции и форматирования даты и информации о карте или счёте.

Пример:
```
mask_account_card("Visa Platinum 1234567812345678")
>>> Visa Platinum 1234 56** **** 5678
get_date("2018-07-11T02:26:18.671407")
>>> 11.07.2018
```

Модуль `generators`

Функция `filter_by_currency` используется для фильтрации банковских операций по валюте.

Пример:
```
filter_by_currency(transactions, "USD")
```

Функция `transaction_descriptions` используется для последовательного получения описаний банковских операций.

Пример:
```
transaction_descriptions(transactions)
```

Генератор `card_number_generator` используется для генерации номеров банковских карт в формате XXXX XXXX XXXX XXXX.

Пример:
```
card_number_generator(1, 10)
```

Модуль `decorators`

Модуль `decorators` содержит декоратор `log`, предназначенный для логирования вызовов функций.

Декоратор записывает дату и время вызова функции, её имя и статус выполнения:

`ok` — функция выполнилась успешно;

`error` — при выполнении функции возникло исключение. В журнал также записываются тип ошибки и переданные аргументы.

Логирование можно настроить двумя способами:

`@log()` — вывод сообщений в консоль;

`@log("my_log.txt")` — запись сообщений в файл my_log.txt.

Пример:
```
from src.decorators import log

@log()
def my_function(x: int, y: int) -> int:
    return x + y

my_function(2, 3)
```

При успешном выполнении в консоль выводится сообщение с датой и временем вызова, именем функции и статусом `ok`.

При возникновении исключения декоратор записывает информацию об ошибке и повторно вызывает исключение, не скрывая его от вызывающего кода.

Модуль `utils`

Модуль содержит функцию `get_operations_from_json`, которая читает данные банковских операций из JSON-файла.

Функция принимает путь к файлу и возвращает список словарей с данными операций. Если файл отсутствует, пуст или содержит данные неподходящего формата, функция возвращает пустой список.

Пример:
```
from src.utils import get_operations_from_json


operations = get_operations_from_json("data/operations.json")
```

Модуль `external_api`

Модуль содержит функцию `convert_transactions_to_rubles`, которая конвертирует сумму транзакции в рубли.

Функция принимает словарь с данными транзакции:

- если валюта операции — рубль (RUB), возвращает сумму без обращения к API;

- для других валют обращается к внешнему сервису конвертации, используя API-ключ из переменной окружения EXCHANGE_RATES_API_KEY;

- возвращает результат конвертации в формате float;

- при ошибке сетевого запроса выводит сообщение и возвращает None;

- если для конвертации отсутствует API-ключ, вызывает исключение ValueError.

Пример вызова:
```
from src.external_api import convert_transactions_to_rubles


amount_in_rubles = convert_transactions_to_rubles(transaction)
```
Для конвертации валют, отличных от RUB, необходимо указать действительный API-ключ в файле .env.

## Логирование

Для регистрации событий работы приложения используется модуль `logging`.

Логи сохраняются в папке `logs/` в корне проекта. Для модулей `masks` и `utils` предусмотрены отдельные файлы:

`logs/masks.log` — записи о результатах маскировки номеров карт и счетов.

`logs/utils.log` — записи об успешном чтении JSON-файлов и возникающих ошибках.

Каждая запись содержит дату и время события, название модуля, уровень важности сообщения и его описание.

Успешные операции записываются с уровнем `INFO`, а ошибки — с уровнем `ERROR`. Например, в журнал `utils.log` попадают сообщения об отсутствии файла, некорректном JSON и неподходящей структуре данных.

Файлы логов открываются в режиме записи при инициализации логирования. При каждом новом запуске соответствующего модуля предыдущие записи в его журнале удаляются.

## Тестирование
Для тестирования используется `pytest`.

Для запуска всех тестов используйте команду:
```
poetry run pytest
```

Для проверки покрытия кода используйте команду:
```
poetry run pytest --cov=src --cov-report=term-missing
```

Для создания HTML-отчёта о покрытии:
```
poetry run pytest --cov --cov-report=html
```

HTML-отчёт сохраняется в папке `htmlcov`.
